# Работа с OKR в ChatGPT и Codex

Когда пользователь присылает ссылку для работы по методике, выбери навык по задаче и открой его полную инструкцию ниже. При одной ссылке без задачи предложи выбор одним вопросом: «С чего начнём: подвести итоги, спланировать квартал или проверить, как он идёт?» Если пользователь уже назвал задачу, переходи сразу к её первому шагу. Квартал уточняй, только когда он нужен. Для ретро аргумент — **планируемый** квартал: «закрыть 2026Q4» означает `okr-retro 2027Q1`.

| Что хочет пользователь | Какой навык открыть |
|---|---|
| Собрать контекст продукта из рабочих документов | [okr-index](skills/okr-index/SKILL.md) |
| Подвести итоги или продолжить начатое планирование | [okr-retro](skills/okr-retro/SKILL.md) |
| Сформулировать цели и решить, что взять в квартал | [okr-scope](skills/okr-scope/SKILL.md) |
| Уточнить этапы, зависимости и риски инициатив | [okr-stages](skills/okr-stages/SKILL.md) |
| Обосновать одну инициативу перед бизнесом | [okr-justify](skills/okr-justify/SKILL.md) |

При обращении к старым командам открой соответствующий навык: [okr-context](skills/okr-context/SKILL.md), [okr-draft](skills/okr-draft/SKILL.md), [okr-debate](skills/okr-debate/SKILL.md), [okr-roadmap](skills/okr-roadmap/SKILL.md), [okr-decompose](skills/okr-decompose/SKILL.md), [okr-plan-deck](skills/okr-plan-deck/SKILL.md). Предложи замену из его инструкции.

## Где взять инструкции и данные

- **По ссылке** читай файлы из той же ветки или ревизии через GitHub, веб-доступ или уже открытый клон. Если чат не может открыть файлы, попроси ZIP репозитория (GitHub → Code → Download ZIP) или текст нужного навыка и его ресурсов.
- **Пути методики.** `resources/` и `scripts/` ведут от папки выбранного навыка, `skills/…` — от корня методики. Для планирования используй [схему](skills/okr-scope/resources/plan_schema.md), [примеры JSON](skills/okr-scope/scripts/fixtures) и [скрипт сборки](skills/okr-scope/scripts/okr-plan.py) с соседней папкой `assets/`. Для индекса есть [схема источников](skills/okr-index/resources/index_schema.md), для экватора — [шаблон](skills/okr-equator/resources/equator-report-template.md) и [скрипты](skills/okr-equator/scripts).
- **Данные продукта** бери из указанного рабочего проекта, вложений, доступного трекера и ответов PO. Примеры из этого репозитория показывают формат. Если прислали только ссылку на методику, для индекса запроси рабочие материалы, для ретро — прошлые цели и факт, для первого плана — рассказ PO.
- **Продолжение.** В рабочем проекте читай и обновляй `.okr/`. В чате используй последние JSON и правки, присланные PO. При наличии файловой среды возвращай обновлённый исходный JSON вместе с собранным HTML или CSV. Для нового чата предложи приложить последние исходники этапа и связанные документы квартала.

## Если чат работает только с текстом

Веди диалог по выбранному навыку и отдай черновик в его исходном формате прямо в ответе. Укажи имя файла и следующую операцию, для которой нужна среда исполнения. Например, для страницы ПЛАН нужны JSON, Python и скрипт с ресурсами, для экватора в PowerPoint — Node.js и pptxgenjs. Отмечай результат проверки и давай ссылку на файл только после фактического запуска проверки или создания файла соответственно.

Для принятия плана нужны подтверждение PO и успешная финальная проверка из навыка. Для переноса в Jira, включая CSV, нужны явное согласие PO на показанный TeamPlanner и успешный `jira-ready`. В режиме без исполнения сохраняй исходник как черновик для продолжения в Codex.
