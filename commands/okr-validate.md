## Использование

```
/okr-validate <path>
```

**Параметры:**
- `<path>` — путь к `OKR-<quarter>.md` или `экватор-<quarter>.md`. Тип
  документа линтер определяет сам: по `## Навигация по слоям` (OKR) или
  `## Главное за 60 секунд` (экватор). На остальных markdown-артефактах
  пайплайна (`roadmap.md`, `KR-EPIC-MAP.md`, контекст-пак) он сообщит, что
  тип не определён, и выйдет с ошибкой — их структура не проверяется.

**Что проверяется:**

| Документ | Проверки |
|---|---|
| `OKR-<quarter>.md` | обе части и обязательные таблицы на месте; у каждого показателя точки А проверяемый источник; коды KR уникальны и в формате `<objective>.<kr>`; PBV 1-9; точки А и B заполнены; таблица дельты покрывает ровно те же KR и нигде не пуста колонка «Наблюдаемый темп»; на каждый KR блок Части 2 с образом результата, явным «не входит» и таблицей HowToDemo с непустой колонкой «Где проверяю»; в Части 1 нет заголовков на отдельные KR; нет запрещённых процессных формулировок KR и размытых шагов HowToDemo; нет длинных тире; нет неэкранированного `\|` в ячейках |
| `экватор-<quarter>.md` | обязательные разделы, PBV 1-9, статус из допустимого enum |

Смысл формулировок линтер не проверяет — это работа `/okr-debate`.

## Инструкция для LLM

Запусти (путь — относительно корня установки, куда `install.sh` синкнул
навыки; обычно `.claude/skills/...`, зависит от выбора при установке):
```bash
python3 <корень установки>/skills/okr-equator/scripts/okr-lint.py <path>
```

Тип документа определяется автоматически. Если PO проверяет заготовку, в
которой обязательные маркеры ещё не проставлены, добавь явный тип:
```bash
python3 <корень установки>/skills/okr-equator/scripts/okr-lint.py --type okr <path>
```
Покажи вывод PO без интерпретации — линтер сам форматирует ошибки. Не
пытайся чинить контент самостоятельно без запроса PO.

## Отчёт

```
<вывод okr-lint.py дословно>

<если exit 1>

```
