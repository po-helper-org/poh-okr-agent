# Обоснование одной инициативы — презентация «брать или нет»

## Ситуация

Решение «брать инициативу в квартал» обсуждалось в переписке и голосом: метрики, цена, риски
каждый раз собирались заново, без единого формата. Бизнесу приходилось верить на слово —
быстрой формы «вот инициатива, вот последствия, вот цена, вот рекомендация» не было.

## Причина

Инструмент планирования работал с кварталом целиком; отдельная инициатива как объект решения
в нём не существовала.

## Решение

Навык `/okr-justify <quarter> <KR>` — короткая HTML-презентация из восьми слайдов, по одной
мысли на слайд: титул (что делаем, тип, оценка, цель, срок) → как проверим результат → метрики
«сейчас → цель» → что меняется в системе → квадрат последствий (будет / не будет, если сделаем
/ не сделаем) → во что обойдётся (дни по видам работ, вопросы к исследованию) → риски → решение
(вопрос к бизнесу, рекомендация, итоговые цифры). Новый `kind: justify` в `okr-plan.py`: схема,
`lint` с гейтами и предупреждениями о перегруженных слайдах и оставшихся местах «уточнить»,
`render`. Название, тип, оценка, цель и команда при наличии Scope берутся из него по номеру KR;
без Scope — из блока инициативы. Каркас слайдов вынесен в общий `deck_page`, им пользуется
и презентация квартала — её вывод байт в байт прежний.

## Как проверить

Собрать обоснование для KR из принятого Scope — факты на слайдах совпадают с планом; `lint`
ругается на незакрытые места и перегруженные слайды; демо из восьми слайдов печатается в PDF
без потерь.

## Уроки

Повторяющееся решение заслуживает своего одностраничного формата: восемь слайдов с фиксированной
структурой собираются из источника данных быстрее и честнее, чем свободный текст. Общий каркас
страниц-презентаций окупается, если следить за неизменностью чужого вывода.
