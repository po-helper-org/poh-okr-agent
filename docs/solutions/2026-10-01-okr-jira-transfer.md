# Перенос плана в JIRA без дублей при прерывании

## Ситуация

План квартала живёт в JSON (Scope → TeamPlanner), а работа — в трекере. Ручной перенос
отнимал время и ошибался: лишние эпики, потерянные истории, расхождение ключей. Отдельной
структуры «инициатива» в трекере нет — KR становится эпиком, подзадачи — историями.

## Причина

Перенос был ручным и одноразовым: никаких отметок о том, что уже перенесено, поэтому прерванный
прогон приходилось начинать заново — с дублями.

## Решение

Навык `/okr-jira`:

1. Нет TeamPlanner — собирает его; есть — просит подтвердить страницу и проверяет `lint --final`.
2. После явного «да» ставит в документе статус принятия и проект переноса, затем запускает
   `okr-plan.py jira-ready`.
3. Создаёт эпики и истории через Atlassian MCP. Ключи пишутся в поле `jira_key` сразу после
   создания каждой задачи — прерванный перенос продолжается без дублей.
4. Нет доступа к Atlassian MCP — `okr-plan.py jira-csv` готовит CSV для импорта.

`lint` проверяет формат поля проекта и ключей.

## Как проверить

Прервать перенос на середине и запустить снова — создаются только недостающие задачи,
`jira_key` у перенесённых на месте. Прогнать `jira-csv` — импорт проходит.

## Уроки

Любой перенос во внешний трекер делать возобновляемым: ключ внешней задачи записывается
в исходный документ сразу после создания — это и идемпотентность, и аудит в одном поле.
