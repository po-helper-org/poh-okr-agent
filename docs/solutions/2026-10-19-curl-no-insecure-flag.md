# curl без ключа отключения проверки TLS в инструкциях установки

## Ситуация

Аудит организации от 18 октября, категория A: инструкция установки начиналась с команды
`curl -ksSL … | bash` — флаг `-k` отключает проверку TLS при загрузке скрипта, который сразу
исполняется. Подмена канала превратила бы инструкцию в запуск чужого кода.

## Причина

Флаг скопировался из рабочей привычки обходить самоподписанные сертификаты во внутреннем
окружении и попал в публичную документацию, где выполняется на машинах пользователей.

## Решение

Флаг `-k` убран во всех местах установки README и в плане реализации из `docs/superpowers/plans/`
(четыре вхождения). Проверка: правка только текстовая, других `-k` и `--insecure` в репозитории
нет (`git grep`). Вторым коммитом из шаблона конфигурации и плана убраны также ключи внутренних
проектов трекера и локальные пути пользователей — заменены нейтральными значениями.

## Как проверить

`git grep -nE '(^| )-k|--insecure'` по репозиторию — пусто. Команда установки из README
исполняется с включённой проверкой сертификатов.

## Уроки

Публичная инструкция установки — код, который выполняют на чужих машинах: никаких флагов,
отключающих проверку подлинности канала. Внутренние привычки окружения не должны просачиваться
в публичные команды.
