# Неверный тип поля JSON ронял скрипт трейсбеком

## Ситуация

Ошибка в типе поля планировочного JSON (строка вместо числа, объект вместо массива) роняла
`okr-plan.py` питоновским трейсбеком. Пользователь видел стек вместо причины; связанные
документы (Retro для Scope, Scope для TeamPlanner) проверялись без объяснения, что именно
в них не так.

## Причина

Скрипт доверял структуре входа: обращение к полям без предварительной валидации, у проверки
связанных документов не было своей диагностики.

## Решение

Проверка структуры по схеме для всех трёх видов документов. Неверный тип поля — ошибка с путём
до поля, а не трейсбэк; связанный документ проверяется и даёт точную причину без обрыва
остальных проверок. В тесты добавлен прогон неверных типов по каждому полю трёх эталонов —
ни одного трейсбека.

## Как проверить

Подставить строку в числовое поле любого вида — `lint` сообщает путь до поля и причину;
прогон юнит-тестов фаззинга проходит без падений.

## Уроки

Скрипт, принимающий JSON от человека или модели, валидирует по схеме до любого обращения
к полям и падает ошибкой с путём, а не стеком. Фаззинг неверных типов по каждому полю — дешёвый
тест этого свойства.
