# Флаг «берём в квартал» закрывает принятие перегруженного плана

## Ситуация

Скоуп планирования всегда шире квартала: одни инициативы берём, другие — кандидаты на потом.
Единого поля «берём / не берём» не было, и принять план можно было с инициативами, по которым
решение ещё не принято. Фокус квартала (лимиты, взвешенные оценки) считался по всему списку
и потому врал.

## Причина

Модель данных описывала «что обсуждается», а не «что решено». Решения жили в голове и в чате —
документ не отличал кандидата от взятого.

## Решение

Поле `initiatives[].in_quarter`: `true` / `false` / нет поля — «не решено». Скоуп шире квартала:
`false` остаётся кандидатом (строка приглушена), без этапов и строк TeamPlanner. Принять план
можно только когда решено по каждой инициативе; фокус считается по взятым. `lint` также проверяет
согласованность TeamPlanner со Scope: добавленный или удалённый в планировщике KR — расхождение,
которое агент обязан сверить с владельцем плана.

## Как проверить

`lint --final` на плане с инициативой без решения — ошибка. Перевести инициативу в `false` —
строка приглушена, этапов и строк планировщика нет, фокус пересчитан по взятым.

## Уроки

Там, где список шире ресурса, хранить решение явно и троично (да / нет / не решено), а гейт
принятия закрывать только полным решением — иначе итоги считаются по мусору.
