# Слэш-команда в харнессе не находила пайплайн без каталога навыков

## Ситуация

Кнопка «Планирование OKR» в разделе «Управление целями» отправляет в чат `/okr-draft <quarter>`.
В харнессе ответ был «Скилла okr-draft нет в каталоге»: шесть шагов пайплайна существовали только
как команды Claude Code в `commands/`, а харнесс резолвит слэш только через каталог навыков —
каталога команд у него нет.

## Причина

Один и тот же слэш в разных средах живёт по-разному: Claude Code показывает команды из `commands/`,
харнесс — только навыки из `skills/`. Процессы пайплайна лежали в командах, потому что репозиторий
исторически начинался как набор команд.

## Решение

У каждой команды появился одноимённый навык: процесс — в `skills/<команда>/SKILL.md`, команда
осталась точкой входа с форматом вызова и отчёта. Установку поправили: в Claude Code команды больше
не синкаются (навыки и так показываются слэш-командами, синк давал каждую `/okr-*` в меню дважды),
ранее синканное снимается при обновлении, чужие файлы не трогаются. Codex, Cline, DevX и Universal
каталога навыков не читают — им команды по-прежнему копируются.

## Как проверить

В харнессе вызвать `/okr-draft` — навык находится и запускается. В Claude Code каждая команда
появляется в меню ровно один раз.

## Уроки

Перенося набор слэш-команд в другую среду, проверить, как она резолвит слэш, до написания кнопок,
которые этот слэш отправляют.
