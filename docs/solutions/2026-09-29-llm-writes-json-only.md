# LLM пишет только JSON, весь вывод считает скрипт

## Ситуация

Страницы ФАКТ и ПЛАН квартального планирования раньше собирались так, что значительную часть
вычисляемого текста писала модель: исходы KR из процентов, итоги, счётчики, шкалы. На реальных
данных цифры то и дело не сходились с трекером, а найти, где именно наврали, было невозможно —
весь документ был одним большим текстом модели.

## Причина

Разделения обязанностей не было: модель отвечала и за факты, и за арифметику, и за вёрстку.
Арифметика — не её работа.

## Решение

В `okr-plan.py` (только стандартная библиотека Python) жёстко разделено: LLM пишет только JSON —
то, что сказал человек или показывает трекер. Всё вычисляемое выводит скрипт: исход KR из
процента, шкалу подзадач, цвет PBV, тексты «что дальше», счётчики, взвешенный итог квартала,
сверку ПЛАН с ФАКТ. `lint` не даёт принять документ с незакрытыми местами. Вёрстка обеих страниц
едина (общие `assets/page.css`, `assets/page.js`). На реальных данных прошлого квартала цифры
пересобранной страницы совпали с исходной.

## Как проверить

Поменять в JSON процент готовности KR — страница пересчитывает исход, счётчики и итоги без участия
модели. `lint` на документе с незаполненными местами — ошибка.

## Уроки

В связке «модель + рендер» модели — только факты, которые негде взять, кроме человека. Всё, что
можно вычислить, считает код: иначе ошибки не отличить от вымысла и не проверить.
