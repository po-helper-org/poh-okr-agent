# Пайплайн планирования квартала переписан под разговор с PO

## Ситуация

Прежний пайплайн планирования квартала был длинным — 8 команд — и начинался с анкеты. Пользоваться
им целиком не выходило: шаги терялись, вход через форму отпугивал, до страниц с результатом
доходили не все.

## Причина

Пайплайн рос по шагам под задачи генерации, а не под то, как реально планирует человек:
планирование начинается с разговора, а не с заполнения полей.

## Решение

Новый пайплайн из четырёх команд вокруг двух HTML-страниц: `/okr-retro → /okr-scope →
/okr-stages → /okr-teamplanner`.

- `/okr-retro` — страница ФАКТ прошлого квартала: готовность каждого KR, подзадачи, переходящее
  в новый квартал. Она же точка входа: видит, на каком этапе планирование остановилось,
  и продолжает оттуда.
- `/okr-scope` — PO свободно рассказывает, что хочет увидеть в квартале (можно голосом), навык
  собирает драфт страницы ПЛАН, дальше итерации и выравнивание.
- `/okr-stages` — декомпозиция инициатив на подзадачи по ролям с условиями, рисками,
  зависимостями.
- `/okr-teamplanner` — CSV «строка на этап» для техлидов, колонки настраиваются шаблоном.

Шесть прежних команд помечены `[deprecated]`: при вызове сообщают об устаревании и предлагают
замену. Кнопка «Планирование OKR» в плагине запускает `/okr-retro` вместо `/okr-draft`.
Проверено: 41 юнит-тест скрипта, страницы в браузере на широком и узком экране, установка
в чистый воркспейс.

## Как проверить

Начать `/okr-retro` на квартале без артефактов — пайплайн проходит по цепочке до CSV. Вызов
устаревшей команды — сообщение с заменой.

## Уроки

Когда пайплайн начинают обходить — сократить его и поставить точку входа туда, где начинается
работа человека, а не данных. Депрекация с указанием замены спасает мышечную память пользователей.
