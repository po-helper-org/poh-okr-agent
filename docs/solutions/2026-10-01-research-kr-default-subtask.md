# Исследовательские KR получают подзадачу сбора требований по умолчанию

## Ситуация

KR с низкой взвешенной оценкой или тегом RESEARCH — это обычно «сначала разобраться, потом
планировать». В заготовке TeamPlanner такие KR оставались без этапов, и на ревью плана
выяснялось, что исследования повисли: ни дней, ни исполнителя, ни первого шага.

## Причина

Заготовка строилась только из инициатив с готовой декомпозицией; для исследовательских KR
естественного первого шага в схеме не было.

## Решение

В `okr-plan.py seed` KR с оценкой ниже 5 или тегом RESEARCH по умолчанию получают одну подзадачу
сбора требований (роль PO). Если у KR уже есть этапы из декомпозиции — они сохраняются, дефолт
не затирает.

## Как проверить

`seed` из Scope с исследовательским KR — у того появилась подзадача сбора требований; KR
с готовыми этапами их сохраняет.

## Уроки

Дефолты заготовки должны кодировать первый шаг там, где работа заведомо начинается с исследования,
— иначе такие пункты молча выпадают из плана.
