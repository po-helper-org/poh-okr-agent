# Навык: OKR Retro (ФАКТ квартала)

## Использование

```
/okr-retro <quarter>
```

`<quarter>` — **планируемый** квартал (`2026Q4`). Ретро подводит итоги
предыдущего (`2026Q3`).

Пайплайн планирования — четыре этапа вокруг двух HTML-документов:

```
/okr-retro → /okr-scope → /okr-stages → /okr-teamplanner
```

## На выходе

```
.okr/<quarter>/plan/retro-<prev>.json   источник истины — его пишешь ты
.okr/<quarter>/plan/retro-<prev>.html   страница ФАКТ — её собирает скрипт
```

Схема JSON, правила вывода и проверки — `skills/okr-scope/resources/plan_schema.md`,
раздел «Retro». Эталон — `skills/okr-scope/scripts/fixtures/retro-2026Q3.json`.
Скрипт — `<корень установки>/skills/okr-scope/scripts/okr-plan.py` (корень —
куда `install.sh` синкнул навыки, обычно `.claude/`). Ниже он — `okr-plan.py`.

## Разделение труда

**Твоя работа — перевести то, что говорит человек, в корректный JSON.** Не
больше.

| Пишешь ты (в JSON) | Считает скрипт (в JSON этого нет) |
|---|---|
| процент готовности `pct` или `"status": "Отменено"` | исход ✔ ◐ ✖ ⊘ |
| подзадачи плана и их `status`: TODO · IN PROGRESS · BLOCKED · DONE | шкалу подзадач и «6 / 10» |
| `pbv` из плана | цвет PBV |
| `next.action` и номер KR следующего квартала | текст «Продолжается в Q4 — KR 1.5» |
| `comment` — слова человека о том, что стоит за процентом | строку факта «90 % — внеплановый; …» |
| `basis` — откуда факт | итог квартала по PBV, счётчики фильтра |

Никогда не пиши в JSON исход, проценты сводки, итог квартала и тексты «что
дальше» — скрипт выведет их сам, одинаково на каждой сборке. Никогда не правь
HTML руками.

Каждый факт — со слов человека или из источника. Не знаешь — `[УТОЧНИТЬ у <кого>]`
в тексте или `null` в числе. Не придумывай процент, статус шага и номер KR.

## Инструкция для LLM

### Этап 0: Где мы

Проверь `.okr/<quarter>/plan/`:

1. `scope-<quarter>.json` со `status: принято` и `phase: stages` → планирование
   дошло до этапа 4. Скажи это и предложи `/okr-teamplanner <quarter>`.
2. `scope-<quarter>.json` принят, `phase: scope` → предложи `/okr-stages <quarter>`.
3. `scope-<quarter>.json` есть, не принят → предложи продолжить: при
   `phase: stages` — `/okr-stages <quarter>`, иначе `/okr-scope <quarter>`.
4. `retro-<prev>.json` принят → ретро готово, предложи `/okr-scope <quarter>`.
5. Иначе — собирай ретро (Этап 1). Черновик ретро есть → продолжай с него.

Готовое не пересобирай. В отчёте назови, с какого места продолжили.

### Этап 1: Каркас из плана квартала

Найди план закрываемого квартала, первое найденное:
- `.okr/<prev>/plan/scope-<prev>.json` — план из нового пайплайна: цели →
  `objectives`, инициативы → `krs`, этапы из заметок → `plan` со статусом `TODO`;
- `.okr/<prev>/OKR-<prev>.md` — план из старого пайплайна;
- `.okr/index/` — если план лежал где-то в воркспейсе.

Ничего нет → спроси PO: «Какие цели и ключевые результаты были в <prev>?
Можно списком или голосом, как удобно». Из ответа собери каркас: `id`,
`title`, `pbv`, `goal`, `plan`.

### Этап 2: Факт

Источники по порядку, каждый — строкой в `basis` с датой:
- экватор `.okr/<prev>/equator/экватор-<prev>.md`;
- трекер: если в `okr-config.md` задан `tracker_projects` и доступен Atlassian
  MCP — статусы эпиков одним запросом на проект, не на каждый KR;
- слова PO.

Спроси PO **одним сообщением** списком KR, где факт неизвестен: «По этим KR не
нашёл готовности — расскажи, что получилось и что дальше». PO может ответить
голосом, сплошным текстом, вразнобой. Разбери ответ по KR сам:

- «сделали» → `pct: 100`; «не начинали» → `pct: 0`; «процентов на 80» → `pct: 80`;
  «сняли», «отменили» → `"status": "Отменено"` и `cancel_reason` с датой, если назвал;
- что стоит за процентом → `comment` его словами, коротко;
- «пришло посреди квартала» → `unplanned: true`;
- какие шаги сделаны → `status` у шагов `plan`: DONE, IN PROGRESS, BLOCKED
  («упёрлись», «ждём другую команду»), TODO; про шаг не сказал — оставь как было;
- «переходит в Q4», «продолжаем» → `next.action: continue`, номер нового KR,
  если назвал; «закрыли» → `close`; «не решили» → `decide`.

Слова PO расходятся с трекером → спроси PO, какой цифре верить, и запиши в
`basis`, откуда взята итоговая. Сам не выбирай.

### Этап 3: Сборка и проверка

```bash
python3 okr-plan.py lint .okr/<quarter>/plan/retro-<prev>.json
python3 okr-plan.py render .okr/<quarter>/plan/retro-<prev>.json .okr/<quarter>/plan/retro-<prev>.html
```

Ошибки lint — это ошибки в JSON: чини их и повторяй. Предупреждения — открытые
места; перечисли их PO.

### Этап 4: Итерации и принятие

PO правит словами («1.2 на самом деле доделали», «2.8 — отменили 20.09») или
комментариями со страницы → правишь JSON → `lint` → `render`.

### Комментарии PO со страницы

PO не правит страницу руками: правым кликом он оставляет комментарий к пункту и
присылает их в чат («Скопировать для агента») или файлом `<файл>.comments.json`.
По каждому комментарию:
1. Найди KR по номеру и поле по разделу (раздел → поле — в `plan_schema.md`,
   «Комментарии PO для агента»).
2. Внеси правку в JSON. Нужен ответ PO, чтобы её сделать, — спроси, не угадывай.
3. После всех правок — `lint` и `render`.
4. Отчитайся списком: номер комментария → что изменил или почему нет.


Когда PO говорит «принято»:
1. `python3 okr-plan.py lint <retro.json> --final`.
2. Есть ошибки → покажи их PO, ретро остаётся черновиком.
3. Чисто → `status: "принято"`, `updated`, `render`.

```
ФАКТ <prev>: .okr/<quarter>/plan/retro-<prev>.html  [черновик | принято]
Итог квартала N % (по PBV). ✔ N · ◐ N · ✖ N · ⊘ N. Продолжается в <quarter>: N.
Открыто: N (lint). Проверка: OK | ошибок N.

── СТОП ── PO: проверьте факт и то, что переходит.
Дальше, после «принято»: /okr-scope <quarter>
```
