# Навык: TeamPlanner

## Использование

```
/okr-teamplanner <quarter>
```

Этап 4 из четырёх: `/okr-retro → /okr-scope → (/okr-stages) → /okr-teamplanner`.

## На выходе

```
.okr/<quarter>/plan/
├── teamplanner-<quarter>.json   источник истины — его пишешь ты
├── teamplanner-<quarter>.html   страница-редактор — её собирает скрипт
└── teamplanner-<quarter>.csv    лист для Google Sheets / Excel — его собирает скрипт
```

Формат, правила вывода и проверки — `skills/okr-scope/resources/plan_schema.md`,
раздел «TeamPlanner»; как запускать скрипт и что значат его ответы — там же,
«Работа со скриптом». Эталон — `skills/okr-scope/scripts/fixtures/teamplanner-2026Q4.json`:
пиши JSON по его образцу. Скрипт — `<корень установки>/skills/okr-scope/scripts/okr-plan.py`
(корень — куда `install.sh` синкнул навыки, обычно `.claude/`). Ниже он — `okr-plan.py`.

## Принцип

Scope отвечает «что хотим и зачем». TeamPlanner — «какой ресурс нужен, кто его
даёт, когда и что ждём на выходе». Этап (на странице — подзадача) — законченный
шаг одной роли в полном цикле: подготовка и согласования → архитектура →
аналитика → разработка → тестирование → инфраструктура → выкатка.

| Роль | Когда |
|---|---|
| `PO` | требования, согласования, приёмка |
| `ADR` | архитектурное решение |
| `SA` | системная аналитика, контракты |
| `BA` | бизнес-аналитика, сбор требований |
| `BE`, `FE` | разработка |
| `QA` | тестирование и отладка |
| `DOPS` | инфраструктура, CI/CD, доступы |
| `RM` | выкатка в прод |
| `EXT[роль]` | ту же работу делает смежная команда: в JSON это `role` + `ext` — id команды |

**Ты пишешь только JSON.** Исполнитель «нет роли в команде» и «внешний ресурс»,
прогресс, статус и сроки KR, подсветку строк, лист для таблицы выводит скрипт.
HTML и CSV руками не правь.

## Как выглядит JSON

```json
{
  "kind": "teamplanner", "quarter": "2026Q4", "team": "Витрина", "po": "Иванова Анна",
  "status": "черновик", "updated": "2026-10-06",
  "scope": {"file": "scope-2026Q4.json"},
  "roles": ["PO", "ADR", "SA", "BA", "BE", "FE", "QA", "DOPS", "RM"],
  "teams": [
    {"id": "back", "name": "Витрина Backend",
     "people": [{"name": "Смирнова Елена", "role": "SA"}, {"name": "Петров Сергей", "role": "BE"}]},
    {"id": "partner", "name": "Биллинг партнёра", "external": true, "people": []}
  ],
  "objectives": [{"id": "1", "title": "Продавать подписку без ручных операций", "krs": [{
    "id": "1.1", "title": "Биллинг партнёра минуя ручную сверку", "pbv": 8, "tag": "", "category": "Change",
    "teams": ["back", "partner"], "owner": "Иванова Анна",
    "result": "Сверка с партнёром идёт автоматически", "comment": "Блокер: стенд партнёра",
    "steps": [
      {"role": "SA", "title": "Сценарии интеграционных тестов", "ext": "", "who": "Смирнова Елена",
       "start": "2026-10-01", "end": "2026-10-09", "status": "TODO",
       "result": "Сценарии согласованы", "action": "Созвон с аналитиком партнёра", "comment": ""},
      {"role": "BE", "title": "Стенд партнёра для тестов", "ext": "partner", "who": "",
       "start": "", "end": "", "status": "BLOCKED", "result": "", "action": "", "comment": ""}
    ]}]}]
}
```

Правила, на которых чаще всего ошибаются:

- `teams` у KR — список id команд из `teams` документа, а не названия.
- `who` — ФИО ровно как в `people` (с тем же написанием); для внешнего этапа — `""`.
- `ext` — id команды с `external: true`; своя команда — `""`.
- `role` — только из `roles`. Если в составе встречается роль вне списка
  (например `Java`), в `people` её можно оставить, но этап всё равно — `BE`.
- Даты — `ГГГГ-ММ-ДД` или `""`. Статус — `TODO`, `IN PROGRESS`, `BLOCKED`, `DONE`.
- `details` у KR — заметка тимлида со страницы («Детальнее»): HTML только из
  тегов `h3 p b strong i em ul ol li br`. Сам пиши её только по просьбе PO;
  чужую не переписывай.

## Инструкция для LLM

### Этап 0: Вводные

1. `scope-<quarter>.json` принят (`status: принято`). Нет → СТОП: «Сначала
   /okr-scope <quarter> до „принято“».
2. У всех инициатив Scope решено `in_quarter` — принятый Scope это гарантирует.
   В TeamPlanner идут только `true`.
3. `teamplanner-<quarter>.json` уже есть → продолжаем с ним (Этап 3), заготовку
   не делаем: в нём могут быть правки техлидов. `seed` и сам откажется его
   перезаписать; `--force` — только если PO прямо попросил начать заново.
4. Нет → заготовка:
   ```bash
   python3 okr-plan.py seed .okr/<quarter>/plan/scope-<quarter>.json .okr/<quarter>/plan/teamplanner-<quarter>.json
   ```
   Переносятся KR, их команды, тип (`category`), `result`, риски и зависимости (в `comment`), этапы
   `/okr-stages`, если были, и роли Scope. Этап смежной команды из `/okr-stages`
   уходит на её команду. Scope с ошибками `lint --final` (например, не решено
   `in_quarter`) `seed` не примет и перечислит, что чинить: иначе KR потерялись бы.

### Этап 1: Состав команд

`teams[].people` — кто есть в командах и с какой ролью. Источник по порядку:
`okr-config.md → teams` (состав), шаблон TeamPlanner команды
(`okr-config.md → teamplanner_template`, лист «Команда»), слова PO. Не знаешь
роль человека — спроси, не угадывай. Человек в двух командах — записью в каждой.
Состав можно не собирать заранее: техлиды заполнят его на странице, во вкладке
«Команда». Смежные команды — `external: true`, людей у них можно не перечислять.

### Этап 2: Этапы по каждому KR

Иди по KR в порядке убывания PBV. Для каждого:

- Пройди полный цикл и оставь только нужные шаги. Для технического KR обычно
  есть `SA → BE → QA → RM`; новый продукт — ещё `PO` (требования) и `ADR`;
  интеграция со смежной командой — её этапы как `EXT[роль]`; новая инфраструктура —
  `DOPS`.
- `title` — действие и объект: «Проектирование импорта каталога», а не «Аналитика».
  Одинаковые шаги по разным объектам — отдельными этапами (каталог, конструктив,
  инвентарь). Не знаешь, как назвать, — название KR.
- `who` — из состава с этой ролью. Роли в командах KR нет — оставь пустым:
  страница покажет «нет роли в команде», это сигнал искать ресурс извне.
- `start`/`end` — если PO или техлид назвал сроки. Не выдумывай.
- `result` — что будет готово и как проверить. `action` — как будем делать.
  Пиши, только если это прозвучало или следует из Scope; пустое поле лучше
  догадки.
- `ACTIVITY` — один-два этапа фоновой работы на весь квартал.
- `comment` у KR — блокеры, сроки, риски из Scope и слов PO.

Собери и проверь — ошибки чини в JSON и повторяй, пока `lint` не скажет `OK`:

```bash
python3 okr-plan.py lint .okr/<quarter>/plan/teamplanner-<quarter>.json
python3 okr-plan.py render .okr/<quarter>/plan/teamplanner-<quarter>.json .okr/<quarter>/plan/teamplanner-<quarter>.html
```

Перед тем как отдать страницу, проверь себя:
- каждый KR из Scope с `in_quarter: true` есть в TeamPlanner (иначе `lint` скажет);
- у каждого KR кроме `ACTIVITY` есть этапы;
- каждое `who` есть в `people`, каждое `ext` — внешняя команда.

### Этап 3: Правки техлидов

Страница — во всю ширину, один экран на цель, KR раскрываются в подзадачи. Слева
две вкладки: «OBJ N из M» — переключение целей, «Команда» — состав (команда ·
тип · ФИО), из него выбираются исполнители. В браузере добавляют и удаляют
подзадачи, меняют тип, название и исполнителя (поле с поиском по составу),
пишут заметку «Детальнее» (`details`). Сроки, статусы, образ результата и
действия подзадач на странице не правятся — их ведёшь ты со слов PO и техлидов.
Правки копятся в браузере и возвращаются кнопкой «Скачать JSON».

Пришёл файл с правками →
1. Положи его на место `teamplanner-<quarter>.json` (прежний сохрани рядом как
   `.bak`, если PO не против).
2. `lint` → `render`. Страница откроется уже с правками. Если у кого-то в
   браузере остались неснятые правки к прошлой версии, страница предложит их
   скачать (`<имя>.old-edits.json`) — такой файл разбирай как обычные правки:
   перенеси нужное в текущий JSON, не заменяй им документ.
3. Прочитай заметки `details` — это мнения, ожидания и границы тимлида;
   учитывай их, когда дальше планируешь этапы KR.
4. Отчитайся коротко: что поменялось (исполнители, новые этапы, состав) и что
   осталось без исполнителя.

Правки словами («SA по каталогу — Смирнова, до 10 октября») — сам правишь JSON,
потом `lint` и `render`.

### Этап 4: Лист для таблицы

```bash
python3 okr-plan.py csv .okr/<quarter>/plan/teamplanner-<quarter>.json .okr/<quarter>/plan/teamplanner-<quarter>.csv
```

Лист: цель → KR «(общий прогресс)» → этапы «Название (РОЛЬ)». Колонки: Название ·
Комментарий · Роль · Исполнитель · Начало · Конец · Статус · Прогресс, % · Образ
результата · Образ действия. На странице то же самое кладёт в буфер кнопка
«Копировать в Sheets» — строка в строку.

`okr-config.md → teamplanner_template` задан (xlsx, csv или ссылка на Google
Sheets) и колонки в нём иные → покажи PO таблицу соответствия колонок и собери
CSV в порядке шаблона из листа по умолчанию.

### Этап 5: Принятие

Когда PO говорит «принято»: `lint --final`. Мешает — покажи что (обычно этапы
без исполнителя). Чисто → `status: "принято"`, `updated`, `render`, `csv`.

## Отчёт

```
TeamPlanner <quarter>: .okr/<quarter>/plan/teamplanner-<quarter>.html  [черновик | принято]
KR N · этапов N: PO N · ADR N · SA N · BA N · BE N · FE N · QA N · DOPS N · RM N.
Без исполнителя N, нет роли в команде N (роли: …), внешний ресурс N.
Таблица: .okr/<quarter>/plan/teamplanner-<quarter>.csv. Проверка: OK | ошибок N.

── СТОП ── Откройте страницу и передайте техлидам: они выбирают исполнителей
прямо на ней, «Скачать JSON» — и файл обратно агенту.
```
