# Навык: Презентация квартала команде

## Использование

```
/okr-present <quarter>
```

Последний шаг: `/okr-retro → /okr-scope → (/okr-stages) → /okr-teamplanner →
(/okr-jira) → /okr-present`. Квартал собран — теперь его нужно рассказать
команде: чем занимаемся, кто за что отвечает и как двигаемся.

## На выходе

```
.okr/<quarter>/plan/present-<quarter>.json        посыл презентации — его пишешь ты
.okr/<quarter>/plan/present-<quarter>.html        презентация — её собирает скрипт
.okr/<quarter>/plan/present-<quarter>.pptx        то же в PowerPoint — только если PO попросил
```

Формат и проверки — `skills/okr-scope/resources/plan_schema.md`, раздел
«Презентация». Эталон — `skills/okr-scope/scripts/fixtures/present-2026Q4.json`.
Скрипты (пути — от корня установки, куда `install.sh` синкнул навыки, обычно
`.claude/`):

- `skills/okr-scope/scripts/okr-plan.py` — проверка (`lint`), HTML (`render`),
  факты для .pptx (`present`);
- `skills/okr-present/scripts/build_present_pptx.js` — .pptx. Нужны Node.js и
  `pptxgenjs` — их ставит `install.sh` (в `skills/okr-equator/scripts`, общий с
  экватором); вручную: `npm install --prefix <корень>/skills/okr-equator/scripts`.

## Принцип

Слайды — как у отчёта-экватора (`/okr-equator`, `resources/brandbook.md`):
синий титул, тёмные слайды-паузы и риски, светлые контентные слайды, Arial и
Courier New. Рассказ идёт **от общего к частному**: сначала картина квартала
целиком, потом прошлое по каждой цели, потом план по каждой цели.

**HERO-паузы.** Каждую часть и каждую цель открывает HERO-слайд: крупный текст
по центру и «Дальше» — о чём пойдёт речь. Тёмные HERO — этапы (Вводная, Ретро,
Планы, Финал), светлые — цели, с цифрами внизу. Они дают визуальную паузу и не
дают презентации слиться в один поток.

**HTML-страница** (`present-<quarter>.html`) — основной формат. Сверху панель
(«На весь экран», «PDF»), слева вкладка «Слайды» с оглавлением, снизу «‹ N / M ›»;
стрелки, пробел, Home/End, F — на весь экран; номер слайда — в адресе
(`#slide=N`). На широком экране — по слайду, на телефоне — лентой. «PDF» —
печать по слайду на страницу. `.pptx` — та же структура, если PO нужен файл
PowerPoint.

Все факты — цели, KR, PBV, итоги прошлого квартала, ответственные,
исполнители, сроки, оценки, риски из заметок Scope — скрипт берёт из принятых
документов: TeamPlanner → его Scope → ретро этого Scope. **Ты не пересказываешь
план в JSON** — только то, чего в документах нет. Поменялся план — правь Scope
или TeamPlanner и пересобирай, а не дописывай факты в `present-<quarter>.json`.

## Слайды

| Часть | Слайд | Откуда |
|---|---|---|
| — | Титул: квартал, команда, главная мысль, период, PO | `message` |
| Вводная | HERO «Картина квартала» | — |
| | Результаты прошлого квартала: исходы KR по целям, итог по PBV, вывод | ретро + `retro_note` |
| | Актуальные риски и проблемы (до 7) | `risks` от PO, затем заметки Scope и внешние команды |
| | Верхнеуровневый roadmap: колонка на цель, KR по PBV | TeamPlanner |
| | Инициативы по спринтам: KR × спринты, в ячейке — тип работ (аналитика, разработка, тесты, выкатка, внешние) | сроки подзадач TeamPlanner, `sprints` / `sprint_weeks` |
| Часть 1 · Ретро | HERO «Ретро», статус по целям прошлого квартала | ретро |
| | По каждой цели: HERO с цифрами исходов → таблица KR — итог, что сделали, что осталось, что переносим | ретро |
| Часть 2 · Планы | HERO «Планы», обзор предстоящих работ: подзадачи по типам работ, KR, оценка, без исполнителя | TeamPlanner |
| | По каждой цели: HERO с цифрами (KR, подзадач, оценка, люди, без исполнителя, риски) → инициативы (PBV, тип, образ результата, кто отвечает, сроки, «из прошлого квартала») | TeamPlanner + Scope |
| | По каждой цели: известные риски — тип, риск, что делаем | `risks` + заметки Scope |
| | По каждой цели: GANTT по сотрудникам — строка на человека, по неделям его KR, цвет — статус; «нет исполнителя» — красным | TeamPlanner |
| Финал | HERO «Как работаем дальше» → как работаем; что нужно от команды | `how`, `asks` |

Нет ретро — нет «Результатов» и части «Ретро». Слайд без данных не выводится.
Скрыть — `skip`: `retro`, `risks`, `sprints`, `gantt`, `asks`.

## Инструкция для LLM

### Этап 0: Вводные

1. `teamplanner-<quarter>.json` есть и принят. Не принят — скажи PO: команде
   показывают принятый план; предложи закончить `/okr-teamplanner` (Этап 5).
   Черновик собрать можно, но `lint --final` его не пропустит.
2. Scope и ретро находятся сами по ссылкам (`scope.file` в TeamPlanner,
   `retro.file` в Scope).
3. `present-<quarter>.json` уже есть — продолжаем с ним, не пиши заново.

### Этап 1: Посыл — спроси PO, коротко

Одним сообщением, не анкетой:

```
Собираю презентацию квартала для команды. Пять вопросов — можно голосом:
1. Главная мысль квартала одним предложением?
2. Что поняли в прошлом квартале и что меняем?
3. Главные риски и проблемы на старте — и что с ними делаем?
4. Как работаем: длина спринта, синки, где статусы?
5. Что нужно от команды после встречи?
```

- `message` — ответ 1; `retro_note` — ответ 2.
- `risks` — ответ 3: `category` (`Внешнее`, `Ресурс`, `Срок`, `Зависимость`,
  `Организация`, `Техническое`, `Общее`), `title` — в чём риск, `detail` — что
  делаем, `kr` — к какому KR (тогда риск попадёт и в разбор цели). Эти риски
  идут первыми; заметки Scope скрипт добавит сам — не переписывай их.
- `sprint_weeks` — длина спринта в неделях (по умолчанию 2) или `sprints` —
  точные даты спринтов, если у команды свой календарь.
- `how`, `asks` — ответы 4 и 5.

Не ответил на что-то — предложи формулировку из документов (`summary` и
`po_brief` Scope, ретро) и спроси «так?». Не выдумывай риски, ритм и просьбы:
нет ответа — поле пустое, слайд не появится.

`objectives[].message` — «зачем» цели простыми словами для команды; нужно,
только если `why` в Scope написан для руководства или пуст.

### Этап 2: Собрать и проверить

```bash
python3 okr-plan.py lint .okr/<quarter>/plan/present-<quarter>.json
python3 okr-plan.py render .okr/<quarter>/plan/present-<quarter>.json .okr/<quarter>/plan/present-<quarter>.html
```

Нужен .pptx — ещё два шага (данные во временный файл, его не храни и не правь):

```bash
python3 okr-plan.py present .okr/<quarter>/plan/present-<quarter>.json /tmp/present-<quarter>.data.json
node <корень>/skills/okr-present/scripts/build_present_pptx.js /tmp/present-<quarter>.data.json .okr/<quarter>/plan/present-<quarter>.pptx
```

Ошибки чини в JSON (или в Scope / TeamPlanner, если ошибка про них).
Предупреждения о Scope и ретро значат, что этих слайдов не будет, — скажи PO.

Перед тем как отдать, пролистай: подзадачи без исполнителя (в GANTT — красным),
KR без сроков (на слайде спринтов — «сроки не заданы»), пустые оценки. Это не ошибка презентации, но PO лучше знать до встречи —
предложи закрыть в TeamPlanner или сказать вслух на встрече.

### Этап 3: Показ

HTML открывается в браузере; PDF — кнопкой «PDF». `.pptx` открывается в
PowerPoint, Keynote или Google Slides; руками его можно править, но при
пересборке правки пропадут — лучше править JSON и документы. «Принято» — когда PO говорит, что показывает в таком виде:
`status: "принято"`, `lint --final`.

## Отчёт

```
Презентация <quarter>: .okr/<quarter>/plan/present-<quarter>.html  [черновик | принято]
Вводная · Ретро <prev> (целей N) · Планы <quarter> (целей N). Рисков N, спринтов N.
До встречи стоит закрыть: <без исполнителя N, KR без сроков N — или «ничего»>.

── СТОП ── Откройте и пролистайте перед встречей.
```
