# Навык: Презентация квартала команде

## Использование

```
/okr-present <quarter>
```

Последний шаг: `/okr-retro → /okr-scope → (/okr-stages) → /okr-teamplanner →
(/okr-jira) → /okr-present`. Квартал собран — теперь его нужно рассказать
команде: чем занимаемся, кто за что отвечает и как двигаемся.

## На выходе

```
.okr/<quarter>/plan/present-<quarter>.json        посыл презентации — его пишешь ты
.okr/<quarter>/plan/present-<quarter>.html        презентация — её собирает скрипт
```

Формат и проверки — `skills/okr-scope/resources/plan_schema.md`, раздел
«Презентация». Эталон — `skills/okr-scope/scripts/fixtures/present-2026Q4.json`.
Скрипт — `skills/okr-scope/scripts/okr-plan.py` (путь от корня установки, куда
`install.sh` синкнул навыки, обычно `.claude/`): проверка (`lint`) и HTML
(`render`). Только Python, Node.js не нужен.

## Принцип

Слайды — как у отчёта-экватора (`/okr-equator`, `resources/brandbook.md`):
синий титул, тёмные слайды-паузы и риски, светлые контентные слайды, Arial и
Courier New. Рассказ идёт **от общего к частному**: сначала картина квартала
целиком, потом прошлое по каждой цели, потом план по каждой цели.

**HERO-паузы.** Каждую часть и каждую цель открывает HERO-слайд: крупный текст
по центру. Тёмные HERO — этапы (Вводная, Ретро, Планы), светлые — цели, с
цифрами внизу. Они дают визуальную паузу и не
дают презентации слиться в один поток.

**HTML-страница** (`present-<quarter>.html`) — основной формат. Сверху панель
(«На весь экран», «PDF»), слева вкладка «Слайды» с оглавлением, снизу «‹ N / M ›»;
стрелки, пробел, Home/End, F — на весь экран; номер слайда — в адресе
(`#slide=N`). На широком экране — по слайду, на телефоне — лентой. «PDF» —
печать по слайду на страницу.

Все факты — цели, KR, PBV, итоги прошлого квартала, ответственные,
исполнители, сроки, оценки, риски из заметок Scope — скрипт берёт из принятых
документов: TeamPlanner → его Scope → ретро этого Scope. **Ты не пересказываешь
план в JSON** — только то, чего в документах нет. Поменялся план — правь Scope
или TeamPlanner и пересобирай, а не дописывай факты в `present-<quarter>.json`.

Скрыть — `skip`: `retro`, `risks`, `sprints`, `gantt`, `asks`.

## Инструкция для LLM

### Этап 0: Вводные

1. `teamplanner-<quarter>.json` есть и принят. Не принят — скажи PO: команде
   показывают принятый план; предложи закончить `/okr-teamplanner` (Этап 5).
   Черновик собрать можно, но `lint --final` его не пропустит.
2. Scope и ретро находятся сами по ссылкам (`scope.file` в TeamPlanner,
   `retro.file` в Scope).
3. `present-<quarter>.json` уже есть — продолжаем с ним, не пиши заново.

### Этап 1: Посыл — спроси PO, коротко

Одним сообщением, не анкетой:

```
Собираю презентацию квартала для команды. Четыре вопроса — можно голосом:
1. Главная мысль квартала одним предложением?
2. Главные риски и проблемы на старте — и что с ними делаем?
3. Длина спринта (по умолчанию 2 недели) или свой календарь спринтов?
4. Что нужно от команды после встречи?
```

- `message` — ответ 1.
- `risks` — ответ 2: `category` (`Внешнее`, `Ресурс`, `Срок`, `Зависимость`,
  `Организация`, `Техническое`, `Общее`), `title` — в чём риск, `detail` — что
  делаем, `kr` — к какому KR (тогда риск попадёт и в разбор цели). Эти риски
  идут первыми; заметки Scope скрипт добавит сам — не переписывай их.
- `sprint_weeks` — ответ 3: длина спринта в неделях (по умолчанию 2) или
  `sprints` — точные даты спринтов, если у команды свой календарь.
- `asks` — ответ 4.

Не ответил на что-то — предложи формулировку из документов (`summary` и
`po_brief` Scope, ретро) и спроси «так?». Не выдумывай риски и просьбы:
нет ответа — поле пустое, слайд не появится.

`objectives[].message` — «зачем» цели простыми словами для команды; нужно,
только если `why` в Scope написан для руководства или пуст.

### Этап 2: Собрать и проверить

```bash
python3 okr-plan.py lint .okr/<quarter>/plan/present-<quarter>.json
python3 okr-plan.py render .okr/<quarter>/plan/present-<quarter>.json .okr/<quarter>/plan/present-<quarter>.html
```

Ошибки чини в JSON (или в Scope / TeamPlanner, если ошибка про них).
Предупреждения о Scope и ретро значат, что этих слайдов не будет, — скажи PO.

Перед тем как отдать, пролистай: подзадачи без исполнителя (в GANTT — красным),
KR без сроков (на слайде спринтов — «сроки не заданы»; в roadmap квартала их нет), пустые оценки. Это не ошибка презентации, но PO лучше знать до встречи —
предложи закрыть в TeamPlanner или сказать вслух на встрече.

### Этап 3: Показ

HTML открывается в браузере; PDF — кнопкой «PDF». Руками HTML не правят: при
пересборке правки пропадут — правь JSON и документы. «Принято» — когда PO говорит, что показывает в таком виде:
`status: "принято"`, `lint --final`.

