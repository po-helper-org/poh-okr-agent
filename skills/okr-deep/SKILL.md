# Навык: Аудитор квартала (OKR Deep)

## Использование

```
/okr-deep <quarter> [--background]
```

## На выходе

```
.okr/<quarter>/OKR-<quarter>.md          полный документ квартала
.okr/<quarter>/okr-<quarter>.html        расширенная страница
.okr/<quarter>/artefacts/                контекст-пак, MANIFEST источников, вердикт
```

## Принцип 0: сначала вопросы, потом документ

`/okr-fast` наружу не ходит и фиксирует только сказанное. Его черновик по
построению неполон: в нём нет сверки с прошлым кварталом, с бэклогом, с
трекером, нет проверки на пересечения KR и скрытые зависимости.

Первым это поднимает deep — и **до** сборки документа. Сначала список вопросов к
PO, потом квартал. Иначе пробелы закрываются правдоподобными догадками, а
документ выглядит готовым, не будучи им.

Вопросы уходят в чат. В документе от вопроса остаётся `[УТОЧНИТЬ]` в той ячейке,
которую он блокирует, — разделов-накопителей нет.

## Стадии

Полностью — `resources/orchestration.md`. Коротко:

| # | Стадия | Что делает |
|---|---|---|
| 0 | seed | читает `OKR-<quarter>-fast.md` **только на чтение** |
| 0а | setup | живая проба источников, `MANIFEST.md` со статусами |
| 1 | context | `/okr-index` + `/okr-context` — первый выход наружу во всём пайплайне |
| 2 | audit | шесть срезов, вопросы в чат, **STOP** |
| 3 | draft | `/okr-draft` как генератор состава, не автор файла |
| 4 | debate | `/okr-debate` — вердикт по измеримости, пересечениям, зависимостям |
| 5 | emit | единственная запись документа + страница |

## Границы навыка

**Seed не переписывается.** `OKR-<quarter>-fast.md` остаётся исходником: неудачный
прогон deep не должен уничтожать то, что PO надиктовал. Все правки идут в
`OKR-<quarter>.md`.

**Недоступный источник — записанное решение, а не умолчание.** Трекер не
отвечает, бэклог не заведён, нексусов нет — источник получает `UNAVAILABLE` в
`MANIFEST.md`, факт оттуда становится `[УТОЧНИТЬ]`. «Пусто» никогда не читается
как «нет данных». Обязательных источников нет: недоступность не блокирует
прогон, но обязана быть зафиксирована.

**Риски — только организационные и только подтверждённые PO.** Не выводятся из
общих соображений («возможна высокая нагрузка», «интеграция может задержаться»).
Неподтверждённый риск не пишется вовсе: команда начинает митигировать то, чего
никто не заявлял.

**PBV не назначается за PO.** Deep может показать перекос («в квартале 66 KR с
весом 8—10 при команде из шести человек») — это вопрос, а не правка.

## Отчёт

```
Аудит <quarter>: <N> вопросов к PO, <M> расхождений с контекстом.
Источники: индекс ✓, Backlog.md ✓, трекер UNAVAILABLE.

<список вопросов>

── СТОП ── PO: ответьте, и я соберу документ.
```

После ответов:

```
OKR <quarter> собран: .okr/<quarter>/OKR-<quarter>.md
Страница: .okr/<quarter>/okr-<quarter>.html
Вердикт дебатов: <A> KR без замечаний, <B> с замечаниями.
Осталось [УТОЧНИТЬ]: <K>.

Дальше: /okr-roadmap <quarter>
```
