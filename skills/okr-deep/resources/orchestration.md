# orchestration — стадии `/okr-deep`

Seed → контекст → аудит → состав → дебаты → одна запись.

## 0. seed

Прочитать `.okr/<quarter>/OKR-<quarter>-fast.md` — **только на чтение**. Deep в
него не пишет ни при каких условиях: неудачный прогон не должен уничтожать то,
что PO надиктовал.

Приоритет источника: локальный `OKR-<quarter>-fast.md`; его нет, но есть
собранный `OKR-<quarter>.md` — прогон идёт в режиме **доработки** (состав не
пересобирается, правятся ячейки с `[УТОЧНИТЬ]` и то, где появился ответ); нет ни
того, ни другого — сказать PO, что сперва нужен `/okr-fast <quarter>` или
`/okr-draft <quarter>`, и остановиться.

Режим фиксируется здесь и задаёт ветку стадии 5.

## 0а. setup — проба источников

Deep первым в пайплайне выходит наружу, поэтому подключения проверяются до
того, как на них опёрся аудит. По каждому источнику — живой read-only вызов и
один из трёх исходов: **доступен**, **не настроен**, **не отвечает**.

| Источник | Проба |
|---|---|
| Индекс воркспейса | есть ли `.okr/index/MANIFEST.md` и насколько он старше правок воркспейса |
| Backlog.md | `backlog task list --type okr --plain` |
| Нексусы OKR | каталог из настроек плагина (`GROUND/NEXUS/okr` по умолчанию) |
| Прошлый квартал | `.okr/<prev-quarter>/` |
| Трекер и вики | read-only вызов MCP, если настроен |

Результат — `.okr/<quarter>/artefacts/MANIFEST.md` со статусом каждого источника.
Недоступный получает `UNAVAILABLE`; факт, который мог прийти только оттуда,
становится `[УТОЧНИТЬ]`, а не «пусто = нет данных».

Интерактивный прогон при недоступном источнике показывает отчёт и спрашивает:
настроить и перезапустить или продолжать без него. Фоновый — помечает и идёт
дальше, список выносит в нотификацию. Обязательных источников нет.

## 1. context

`/okr-index` (если индекса нет или он устарел) и `/okr-context <quarter>`.
Это первая стадия всего пайплайна, где вообще поднимаются внешние источники:
`/okr-fast` их не читает по построению, поэтому seed несёт только слова PO — и
сверять его есть с чем именно здесь.

Выход — `artefacts/okr-context-pack.md`.

## 2. audit

`audit.md`: шесть срезов, вопросы в чат, **STOP** в интерактивном прогоне.

## 3. draft

`/okr-draft <quarter>` работает здесь **генератором состава, а не автором файла**:
на вход обогащённый seed плюс ответы PO, на выход — текст целей и ключевых
результатов, который возвращается в прогон.

Запрет буквальный: на этой стадии `/okr-draft` ничего не сохраняет. Своим
сохранением он положит собственный документ поверх собранного и потеряет
ответы аудита. Единственная запись — стадия 5.

## 4. debate

`/okr-debate <quarter>` по собранному составу: измеримость, реалистичность
(sandbagging и недостижимость), пересечения KR, скрытые зависимости.

Вердикт возвращается в прогон таблицей «KR — проблема — предложение». Deep
**не исправляет KR по вердикту сам**: правка формулировки — решение PO. Строки
вердикта уезжают в документ отдельным разделом и на страницу — значком у KR.

## 5. emit

Единственная запись за прогон:

1. Собрать `OKR-<quarter>.md`. Ветка по режиму со стадии 0:
   - **первичная сборка** — документ пишется целиком;
   - **доработка** — существующий состав сохраняется как есть, правятся только
     ячейки с `[УТОЧНИТЬ]` и строки, где появился ответ. Номера KR не
     перенумеровываются, ручные правки PO не затираются.
2. Прогнать гейт структуры:
   ```sh
   python3 <skills_path>/okr-deep/scripts/okr-doc-lint.py .okr/<quarter>/OKR-<quarter>.md
   ```
   Ненулевой код — документ не по шаблону: починить и прогнать снова, не
   сохранять сломанный.
3. Собрать страницу:
   ```sh
   python3 <skills_path>/okr-fast/scripts/okr-html-export.py .okr/<quarter>/OKR-<quarter>.md --stage deep
   ```
   Провал скрипта — строка в отчёт, а не остановка прогона: документ уже записан.
4. Обновить frontmatter: `stage: deep`, `version` +1, дата прогона.

## Деградация — норма, не сбой

Нет индекса, нет бэклога, MCP не отвечает, нексусов не существует — прогон идёт
дальше с записанными статусами. Останавливается deep только в двух местах: STOP
аудита в интерактивном режиме и отсутствие seed вовсе.
