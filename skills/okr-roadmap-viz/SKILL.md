# Навык: Roadmap цели — md → граф → html

## Использование

```
/okr-roadmap-viz <slug|папка> [что сделать]
```

`<slug>` — короткое имя цели латиницей (`goal-03`), папка — `.okr/roadmap/<slug>/`.
Первый запуск собирает roadmap из наработок, следующие — правят его. Если PO вставил
промпт из панели комментариев страницы — это тот же навык, этап 4.

## На выходе

```
.okr/roadmap/<slug>/roadmap.md     паспорт — пишешь ты
.okr/roadmap/<slug>/backlog/*.md   задачи своего трека — пишешь ты
.okr/roadmap/<slug>/roadmap.json   граф и номера — пишет lint
.okr/roadmap/<slug>/roadmap.html   страница — пишет build
```

Формат и проверки — `skills/okr-roadmap-viz/resources/format.md`. Эталон —
`skills/okr-roadmap-viz/scripts/fixtures/sample/`. Скрипт —
`skills/okr-roadmap-viz/scripts/roadmap.py` (путь от корня установки, обычно `.claude/`),
только Python 3:

```bash
python3 <корень>/skills/okr-roadmap-viz/scripts/roadmap.py lint  .okr/roadmap/<slug>
python3 <корень>/skills/okr-roadmap-viz/scripts/roadmap.py tree  .okr/roadmap/<slug>
python3 <корень>/skills/okr-roadmap-viz/scripts/roadmap.py build .okr/roadmap/<slug>
```

Запускай из корня воркспейса: путь к папке попадает в промпт, который страница
отдаёт агенту.

## Принцип

Три шага, у каждого свой исполнитель:

| Шаг | Кто | Что |
|---|---|---|
| Декомпозиция | ты (LLM) | Наработки → `roadmap.md` и `backlog/*.md`: треки, этапы, задачи, даты, роли, зависимости, вехи, блокеры, вопросы |
| Проверка и граф | `roadmap.py lint` | Схема, ссылки, циклы, порядок дат по зависимостям, номера 3.7.1 → `roadmap.json` |
| Визуализация | `roadmap.py build` | Один `roadmap.html` из md по шаблону. Одинаковые md — байт в байт одинаковая страница |

Ты работаешь только с md. В html и json руками не лезешь: номера, недели, порядок,
полосы и стрелки считает скрипт. Вид страницы зашит в шаблон
`scripts/assets/` — его не правят под конкретную цель.

## Инструкция для LLM

### Этап 0: Вводные

1. Папка `.okr/roadmap/<slug>/` есть → прочитай `roadmap.md`, запусти `tree`: это
   текущее дерево с номерами, файлами и зависимостями. Дальше — этап 2 или 4.
2. Папки нет → собери наработки: что PO приложил или назвал (выгрузка GanttPRO,
   `.xlsx`/`.csv`, заметки, `.okr/<quarter>/plan/scope-*.json`, `teamplanner-*.json`,
   эпики Jira, Confluence), плюс разговор. Индекс воркспейса — `.okr/index/`.
3. Спроси PO только то, без чего не собрать, одним сообщением, не больше трёх
   вопросов: название цели, какой трек свой (раскладывается на задачи), что брать
   из источников, если они спорят. Остальное — бери из наработок.

### Этап 1: Декомпозиция в md

1. `roadmap.md` по формату: роли, выходные недели, целевые состояния цели, все треки.
   У чужих треков — результат, план по ролям, целевые состояния. У своего — `- свой: да`,
   `- нумерация: <N>` (номер цели или трека, как PO привык: 3 → 3.1, 3.7.1) и этапы.
2. Каждая задача своего трека — файл `backlog/task-<N> - <название>.md`. `id` —
   `task-1`, `task-2` … подряд; при импорте можно сохранить id источника (`t84`,
   `GDS-123`). id не переиспользуй и не меняй: на них держатся зависимости и
   комментарии.
3. Что известно — пиши; чего нет — оставь пустым. Даты, людей и проценты не выдумывай.
   Неизвестное, которое надо решить, — подзадача `ВОПРОС: …` со статусом
   «Заблокировано»; то, что мешает, — `type: blocker` с датой, когда снимется.
   Контрольные точки «готовы к …» — `type: milestone`.
4. Порядок — `ordinal` шагом 10 (10, 20, 30), чтобы потом вставлять между.
5. Номера (3.7.1) в `title` не пиши — их ставит скрипт. Сослаться на задачу в
   названии — `{#task-12}`.
6. Больше 20 задач — пиши файлы коротким скриптом из разобранного источника, а не по
   одному: так меньше опечаток в полях.
7. Есть функциональная декомпозиция (WBS из MS Project / GanttPRO XML, дерево фич) —
   это второе измерение тех же работ, а не новые задачи. Сначала сопоставь её с
   этапами и покажи PO таблицу «ветка → этап и задачи» с пробелами в обе стороны.
   После согласования: дерево — в `### Фичи` своего трека (2–3 уровня), задачам —
   `feature:`. Узел без своих сроков — подзадача существующей задачи с её окном и
   пометкой «оценки нет»; листья — чек-листом в теле файла. Решения — `type: blocker`
   с датой «пятница перед стартом зависимой работы», результаты — вехи с датой
   финиша работы, от которой зависят. Даты, которых нет ни в одном источнике, не
   выдумывай.

### Этап 2: Проверка

1. `lint`. Ошибки исправь в md и повтори, пока не «Принято». Своими словами
   ошибку не обходи: не удаляй зависимость, чтобы убрать цикл, — спроси PO, какая
   из связей лишняя.
2. Предупреждения о датах по зависимостям — покажи PO списком: это либо опечатка в
   дате, либо реальное нарушение плана. Молча даты не сдвигай.
3. `tree` — сверь дерево с источником: все ли задачи на месте, правильно ли
   вложены, верны ли номера относительно того, к чему привык PO.

### Этап 3: Сборка

`build` → `roadmap.html`. Отдай файл PO (или путь к нему) и одной строкой скажи,
что в нём: треков, этапов, задач, со сроками, предупреждений.

### Этап 4: Комментарии со страницы

На странице PO комментирует любой элемент карты (правый клик или режим
«Комментировать»), двигает даты и строки мышью, добавляет задачи. «Скопировать
промпт» отдаёт всё одним сообщением: пронумерованные комментарии с адресом (номер,
файл, неделя) и список правок, сделанных на странице.

1. Правки страницы переноси в md как есть: даты, статусы, роли, зависимости —
   в поля файла; новая задача — новый файл со следующим `task-<N>`; новый порядок —
   `ordinal` по порядку; перенос — `parent`/`stage`; комментарий о состоянии — строка
   в разделе `## Комментарии` файла.
2. Комментарии — по одному: что просят, в каком файле, что меняешь. Неясно — не
   угадывай, вопрос PO в отчёте.
3. Номера в промпте — на момент той сборки; ищи задачу по файлу или id, не по номеру.
4. `lint` → `build`. После пересборки правки страницы в браузере сбрасываются сами —
   они уже в md. Комментарии PO очищает кнопкой, когда прочитает отчёт.

## Отчёт

```
Roadmap «<цель>»: .okr/roadmap/<slug>/roadmap.html
Треков N, этапов N, задач N (со сроками N), зависимостей N. Предупреждений: N.

По комментариям: 1 — сделано (<файл>), 2 — вопрос: <…>, …
Правки страницы: перенесено N.

── СТОП ── Откройте страницу. Новые правки — комментариями и «Скопировать промпт».
```
