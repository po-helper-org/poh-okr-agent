# Формат roadmap: `roadmap.md` + `backlog/`

Папка roadmap — одна цель (OKR-объектив) со всеми её треками:

```
.okr/roadmap/<slug>/
  roadmap.md        паспорт: роли, выходные, целевые состояния, треки, этапы своего трека
  backlog/          задачи своего трека — по файлу на задачу
    task-1 - Интервью с организаторами.md
  roadmap.json      граф зависимостей и номера — пишет `roadmap.py lint`, руками не править
  roadmap.html      страница — пишет `roadmap.py build`, руками не править
```

Пишет и правит агент только `roadmap.md` и `backlog/*.md`. Всё вычисляемое — номера
3.7.1, недели, граф, порядок, страница — делает скрипт. Эталон —
`scripts/fixtures/sample/`.

## Модель

- **Цель** — вся папка. Заголовок страницы — `title` из `roadmap.md`.
- **Трек** — строка обзора. У чужих треков — результат, план по ролям и целевые
  состояния. **Свой трек** (ровно один, `- свой: да`) раскладывается на этапы и задачи.
- **Этап** — группа задач своего трека (3.3, 3.4 …).
- **Задача** — файл в `backlog/`. Бывает задачей с периодом, вехой (одна дата) или
  блокером (дата, когда снимется). Задачи вкладываются через `parent`.
- **Целевое состояние** — веха roadmap: у трека (одна неделя) или у всей цели
  (может длиться несколько недель).

## `roadmap.md`

```markdown
---
title: Цель 01. Онлайн-продажа абонементов
start: 2026-09-28          # необязательно: первая неделя шкалы; по умолчанию — неделя самой ранней даты
---

Свободный текст до первого раздела сборка не читает.

## Роли

- PO | Product Owner | #c98a00          ключ | расшифровка | цвет (#rrggbb, необязательно)
- SA | Системный аналитик | #3b6fd4

## Выходные недели

- 2026-12-28..2027-01-08                 любая дата недели или диапазон; неделя заштрихована

## Целевые состояния цели

- 2027-03-22..2027-04-02 | Кратко | Полная формулировка    диапазон = сколько недель длится

## Трек 1. Исследование

### Результат

Текст результата трека.

### План по ролям

- PO: 2026-10-05..2026-10-30, 2026-11-16..2026-11-20
- SA: 2026-10-12..2026-11-06

### Целевые состояния

- 2026-11-06 | Кратко | Полная формулировка                   одна дата

## Трек 2. Продажа абонементов

- свой: да
- нумерация: 2                           префикс номеров: 2.1, 2.2.1 …

### Результат
### План по ролям                        у своего трека необязателен: полосы строятся по задачам

- analytics: Аналитика и требования      id: название; порядок строк = порядок этапов
- dev: Разработка продажи
```

Роли по умолчанию, если раздела нет: PO, SA, BE, FE, DEVOPS, DELIVERY.
Даты везде — `ГГГГ-ММ-ДД`.

## `backlog/<id> - <название>.md`

Файл задачи — frontmatter и текст, как у [Backlog.md](https://github.com/MrLesk/Backlog.md).
Имя файла роли не играет, связь — по `id`.

```markdown
---
id: task-6
title: API продажи абонемента
status: Открыт            # Открыт | В работе | Заблокировано | Выполнено (To Do / In Progress / Done тоже)
role: BE                  # ключ из «## Роли»
type: task                # task | milestone | blocker
stage: dev                # id этапа; у подзадачи не нужен — этап наследуется от родителя
parent: task-5            # необязательно: задача-родитель
ordinal: 20               # порядок среди соседей; без него — по id
start: 2026-12-07         # у задачи — период start..end
end: 2027-01-22
date: 2026-12-04          # у вехи и блокера — одна дата (или end)
progress: 40              # 0…100
dependencies: [task-4, stage:analytics]   # «стартует после»: задачи и целые этапы
customer: Иванова         # заказчик
assignee: Команда Core    # исполнитель
approver: Петров          # согласующий
short: Витрина            # краткое название на шкале
---

Описание: что делаем, критерий готовности, ссылки. Попадает во вкладку «Описание».

## Комментарии

- 2026-11-02: черновик отправлен бизнесу     заметки о состоянии, по дате
```

Обязательны `id`, `title`, `role`. Остальное — по мере знания: задача без дат
видна в дереве, но не на шкале.

В `title` можно сослаться на другую задачу: `Решение по итогам {#task-12}` — на
странице подставится её номер.

### Нумерация

Считает скрипт, в файлах номеров нет: `<нумерация>.<k>` — сначала задачи своего трека
без этапа, затем этапы в порядке «### Этапы», внутри — по `ordinal`, вложенные —
`2.3.1.2`. Не нумеруются блокеры и задачи, чьё название начинается с `БЛОКАТОР`,
`ВОПРОС`, `ЖДЕМ`, `ВЛИЯЕТ`.

## Проверки `lint`

Ошибка — сборки не будет:

- нет `id`, `title`, `role`; повтор `id`; роль, этап или родитель, которых нет;
- дата не `ГГГГ-ММ-ДД`, `end` раньше `start`, `progress` вне 0…100;
- зависимость на несуществующую задачу или этап, на себя, на свой этап, на предка
  или потомка; цикл зависимостей (в том числе через этап); цикл `parent`;
- `{#id}` в названии на несуществующую задачу;
- задачи есть, а своего трека нет, или своих треков больше одного; этапы у чужого трека.

Предупреждение — сборка будет:

- задача стартует не позже финиша того, после чего должна идти (на странице — подсветка);
- веха без даты; `progress: 100` без статуса «Выполнено»; одинаковый `ordinal` у соседей;
- этап без задач; поле или раздел, которые сборка не читает.

## `roadmap.json`

Пишет `lint`: этапы с номерами и составом, по каждой задаче — номер, файл, родитель,
этап, тип, статус, роль, даты, `after` (от чего зависит) и `before` (что ждёт её,
с раскрытием зависимостей на этапы), предупреждения. Для агента — быстрый ответ на
«что сдвинется, если сдвинуть X».

## Страница и комментарии

`roadmap.html` — один файл без внешних запросов: обзор треков, страница своего трека
с этапами или ролями, карточка задачи, экспорт в `.xlsx`. Правки мышью (даты,
статусы, порядок, новые задачи) хранятся в браузере и в md сами не попадают.

Верхняя панель — канал правок для агента: правый клик по любому элементу карты
(задача, этап, трек, роль, целевое состояние, неделя в шапке) или режим
«Комментировать» → комментарий. «Скопировать промпт» отдаёт одним сообщением все
комментарии (с адресом: номер, файл, неделя) и все правки, сделанные на странице.
Агент вносит их в md и пересобирает страницу; после пересборки правки страницы
сбрасываются — они уже в md.
