# Данные планирования квартала

Источник истины каждого этапа — JSON-файл. HTML-страницы и таблица TeamPlanner
пересобираются из него скриптом `okr-plan.py`, руками не правятся.
Правка PO → правка JSON → `lint` → `render`.

## Работа со скриптом

Скрипт — `<корень установки>/skills/okr-scope/scripts/okr-plan.py` (корень —
куда `install.sh` синкнул навыки: `.claude/`, `.agents/` или `.clinerules/`).
Запускается из корня воркспейса, пути к файлам — от него же. Нужен только
Python 3, без пакетов.

| Команда | Что делает |
|---|---|
| `okr-plan.py lint <file.json> [--final]` | проверяет документ любого вида (`kind`); `--final` — по правилам принятия |
| `okr-plan.py render <file.json> <out.html>` | собирает страницу ФАКТ, ПЛАН или TEAMPLANNER |
| `okr-plan.py seed <scope.json> <teamplanner.json> [--force]` | заготовка TeamPlanner из принятого Scope; существующий файл не перезаписывает без `--force` |
| `okr-plan.py csv <teamplanner.json> <out.csv>` | лист TeamPlanner для Google Sheets / Excel |

Что отвечает скрипт и что делать:

| Ответ | Смысл | Что делать |
|---|---|---|
| `OK` | документ в порядке | показать PO страницу |
| `! …` (предупреждение) | открытое место или гейт черновика | перечислить PO, в черновике не мешает |
| `НЕ ПРОШЁЛ: N ошибок` и `- …` | данные неверны | исправить JSON по тексту ошибки и повторить |
| `…: структура не совпадает со схемой` / ошибки вида `teams: ожидается список [...]` | в JSON объект, список или значение не на своём месте | привести поле к схеме ниже (путь в ошибке — `objectives[0].krs[1].teams`) |
| `файл не найден`, `не JSON — строка N` | нет файла или сломан синтаксис | проверить путь; починить JSON (запятые, кавычки) |

Код выхода: 0 — успех, 1 — ошибки, 2 — неверный вызов (скрипт печатает
справку). `render`, `seed` и `csv` на документе со сломанной структурой не
работают: сначала `lint`.

Страницы ФАКТ и ПЛАН собираются в одной вёрстке: `scripts/assets/page.css`
и `page.js` — общие, `fact.css` и `scope.css` — своё у каждой. TEAMPLANNER —
та же `page.css` плюс свой редактор `teamplanner.js` / `teamplanner.css`.

```
.okr/<quarter>/plan/
├── retro-<prev>.json / .html        Этап 1 · /okr-retro
├── scope-<quarter>.json / .html     Этапы 2–3 · /okr-scope, /okr-stages
└── teamplanner-<quarter>.json / .html / .csv   Этап 4 · /okr-teamplanner
```

`<quarter>` — планируемый квартал (`2026Q4`), `<prev>` — закрываемый (`2026Q3`).
Эталоны — `scripts/fixtures/retro-2026Q3.json` и `scripts/fixtures/scope-2026Q4.json`.

## Общие правила

- `status`: `черновик` → `принято`. «Принято» ставится только после явного
  «принято» от PO и чистого `lint --final`. У принятого документа `lint` всегда
  проверяет по строгим правилам.
- Неизвестное — `[УТОЧНИТЬ у <кого>]` прямо в тексте. На экране такие места
  подсвечены. В черновике допустимы, в принятом документе — нет в ключевых полях.
- `status` KR или инициативы: `Активна` (можно не писать) или `Отменено`. У
  отменённой обязателен `cancel_reason` — причина и дата решения. Отменённая
  остаётся в документе, но не идёт в счётчики, проверки этапов и TeamPlanner.
- Статус подзадачи (шага плана, этапа): `TODO` · `IN PROGRESS` · `BLOCKED` · `DONE`.
- PBV в плане — целое 1–9 (9 — коммитмент с дедлайном, не больше двух на квартал).
  В факте допустимы 0 и `null`: так вес записан в трекере.
- id KR — `<id OBJ>.<N>`: `1.1`, `1.2`, `2.1`.

## Retro (страница ФАКТ) — `kind: "retro"`

LLM переводит в JSON то, что говорит человек или показывает трекер, — и только.
Всё остальное на странице выводит `okr-plan.py`: исход KR, шкалу этапов, цвет
PBV, тексты «что дальше», счётчики фильтра, сводку и итог квартала. Эти поля в
JSON не пишутся — их там нет.

| Поле | Что это |
|---|---|
| `quarter`, `next_quarter` | закрываемый и планируемый квартал |
| `team`, `po`, `updated` | шапка |
| `basis[]` | откуда факт: трекер и дата выгрузки, что уточнено со слов PO и когда. По строке на источник |
| `objectives[]` | `id`, `title`, `outcome` — ради чего цель, одной фразой, `krs[]` |
| `krs[].id`, `title` | номер из плана квартала (`1.1`, `1.1.E1`, `3.1.1e`) и название |
| `krs[].pbv` | вес из плана: целое 0–9; `null`, если не задан |
| `krs[].pct` | фактическая готовность, целое 0–100; `null`, если оценки нет |
| `krs[].status` | `Отменено`, если KR отменён — тогда процент не нужен |
| `krs[].unplanned` | `true`, если KR пришёл после старта квартала («влёт») |
| `krs[].comment` | что стоит за процентом, со слов человека: «демо перенесли, коммитмент 30.09 сорван» |
| `krs[].goal` | образ результата из плана |
| `krs[].plan[]`, `deps[]` | шаги: `role` (латиница заглавными: `BE`, `SA`, `RELEASE`), `step`, `status` |
| `krs[].risks[]`, `who[]` | риски и исполнители |
| `krs[].next` | `action` и, если есть, `kr` — номер KR в следующем квартале; `note` для `other` |
| `krs[].cancel_reason` | для отменённого: причина и дата решения |

`next.action`:

| action | Когда | На странице |
|---|---|---|
| `continue` | работа идёт дальше в следующем квартале | «Продолжается в Q — KR `kr`» |
| `close` | закрыт, ничего не переходит (по умолчанию для 100 %) | «Закрыт — снять с контроля» |
| `drop` | отменён (для `status: Отменено` ставится сам) | «Отменён — `cancel_reason`» |
| `decide` | судьба не решена | «Решить: продолжаем, переносим или закрываем» |
| `other` | особый случай | текст из `note` |

### Что выводит скрипт

| На странице | Правило |
|---|---|
| Исход KR | `status: Отменено` → ⊘ отменено; `pct` нет → ? не оценён; 100 → ✔ закрыт; 0 → ✖ не сделано; иначе ◐ частично |
| Ступень PBV | 8–9 высокий · 4–7 средний · 1–3 низкий · 0 нулевой · нет — пунктир |
| Шкала подзадач | деление на шаг плана, цвет по статусу; число — DONE из всех |
| Факт в карточке | «`pct` % — внеплановый; `comment`» |
| Итог квартала | среднее `pct`, взвешенное по PBV, по KR с исходом ✔ ◐ ✖ и PBV ≥ 1; рядом простое среднее; округление половиной вверх |
| Фильтр | счётчики по исходам |

## Scope — `kind: "scope"`

| Поле | Что это |
|---|---|
| `quarter`, `team`, `po`, `updated`, `summary` | шапка |
| `phase` | `scope` (этап 2) или `stages` (после этапа 3) |
| `retro.file` или `retro_skipped` | ссылка на Retro или причина, почему его нет |
| `po_brief` | исходный рассказ PO, как был продиктован |
| `teams[]` | `id`, `name`, `external: true` для смежных команд |
| `roles` | роли этапов, по умолчанию `PO, SA, BE, FE, ADR` (`okr-config.md → role_tags`) |
| `objectives[]` | `id`, `title`, `why` (проблема и эффект), `activity: true` для поддержки, `initiatives[]` |
| `initiatives[].teams` | id команд из `teams` |
| `initiatives[].pbv`, `tag` | PBV и тег: пусто · `RESEARCH` · `POC` · `BUG` · `ACTIVITY` |
| `initiatives[].in_quarter` | берём в квартал: `true` / `false`; нет поля — не решено |
| `initiatives[].status`, `cancel_reason` | `Отменено` и причина, если инициативу сняли при планировании |
| `initiatives[].from_retro` | id KR из Retro, если это продолжение или доделка |
| `initiatives[].result` | образ результата — что можно показать в конце квартала |
| `initiatives[].before`, `after` | БЫЛО → СТАЛО для технических изменений, заполняются парой |
| `initiatives[].open` | открытые вопросы по инициативе |
| `initiatives[].notes` | заметки этапа 3 (ниже) |
| `retro_dropped[]` | `id`, `reason` — что из Retro осознанно не берём |
| `open_questions[]` | открытые вопросы квартала |

### Берём в квартал — `initiatives[].in_quarter`

Скоуп шире квартала: в нём все кандидаты, а в квартал идёт только часть.

| Значение | Смысл | Этапы (`/okr-stages`) | TeamPlanner |
|---|---|---|---|
| `true` | идёт в квартал | обязательны | да |
| `false` | остаётся в скоупе кандидатом, в этот квартал не идёт | не нужны | нет |
| нет поля | не решено | проверяются | — (принять нельзя) |

`false` — не отмена. Отмена (`status: Отменено`) — инициативу сняли совсем, с
причиной и датой. `false` — «хорошая идея, но не в этот квартал»: строка на
странице приглушена, но не зачёркнута. Отменённая инициатива не может иметь
`in_quarter: true`. Переходящий KR ретро, чья инициатива `false`, считается
решённым: в сверке с ретро он идёт в «не берём».

### Заметки этапа 3 — `initiatives[].notes`

| Поле | Что это |
|---|---|
| `description` | описание инициативы: зачем, что входит, что нет |
| `stages[]` | `role`, `title`, `ext: true` для шага внешней команды, `status` (по умолчанию `TODO`) |
| `conditions[]` | что должно быть выполнено, чтобы цель была достижима |
| `risks[]` | что может пойти не так и к чему приведёт |
| `dependencies[]` | от кого и чего зависим |
| `uncertainties[]` | что пока неизвестно и надо устранить (обязательно для RESEARCH и POC) |

## Что проверяет `lint`

Ошибка блокирует всегда. «Гейт» блокирует только принятие (`--final` или
`status: принято`), в черновике выводится предупреждением.

| Проверка | Retro | Scope | Этапы |
|---|---|---|---|
| Структура: объекты, списки и значения на своих местах | ошибка | ошибка | ошибка |
| Формат кварталов, id KR, уникальность | ошибка | ошибка | — |
| Источник факта (Retro) и why (Scope) заполнены, без `[УТОЧНИТЬ]` | гейт | гейт | — |
| PBV, pct, tag, status, статусы подзадач, next.action из допустимых значений | ошибка | ошибка | ошибка |
| У отменённого KR / инициативы есть причина и дата | гейт | гейт | — |
| У каждого KR есть процент или отметка «отменён» | гейт | — | — |
| Что дальше: у продолжения — номер KR, у other — текст | гейт | — | — |
| 100 % при незакрытых подзадачах, 0 % при сделанных | предупреждение | — | — |
| Команды инициативы описаны в teams | — | ошибка | — |
| PBV у каждой инициативы | — | гейт | — |
| `in_quarter` — `true`/`false`; у отменённой не `true` | — | ошибка | — |
| По каждой инициативе решено, берём ли в квартал | — | гейт | — |
| Образ результата; при PBV ≥ 7 — без `[УТОЧНИТЬ]` | — | гейт | — |
| БЫЛО/СТАЛО парой | — | ошибка | — |
| Каждый KR Retro с `continue` есть в Scope (`from_retro`) или в retro_dropped | — | гейт | — |
| Описание инициативы; этапов ≥ 1, при PBV ≥ 7 — ≥ 3 (кроме `in_quarter: false`) | — | — | гейт |
| Роль этапа из `roles` | — | — | ошибка |
| У RESEARCH/POC есть неопределённости | — | — | гейт |
| 3–5 целей, ≤ 6 инициатив на цель, ≤ 20 всего, ≤ 2 с PBV 9 — по тем, что идут в квартал | — | предупреждение | — |

## Страница ПЛАН: что выводит скрипт

| На странице | Правило |
|---|---|
| Колонки ASIS / TOBE | `before` / `result` инициативы |
| `+` у номера | нет `from_retro` и цель не поддержка — новая инициатива |
| Зачёркнутая строка | `status: Отменено` |
| Колонка «В квартал» | `in_quarter`: ✓ да · нет · ? (не решено); строка с `false` приглушена |
| Шкала подзадач | этапы из заметок, цвет по статусу (после `/okr-stages`) |
| Шапка | цели; инициативы — всего, в квартал, не решено; PBV ≥ 7 и 9, из прошлого квартала — по тем, что в квартал; отменено; сверка с Retro: продолжается, в плане, не берём, не решено |
| Открытые вопросы | `open_questions`, «берём в квартал?» по нерешённым, `open` и места с `[УТОЧНИТЬ]` инициатив, идущих в квартал |
| Фильтр | инициативы по командам |

## TeamPlanner — `kind: "teamplanner"`

Третья форма: каждый KR, взятый в квартал (`in_quarter: true`), разложен на
операционные этапы полного цикла — от подготовки до выкатки. Цель — быстро
расписать, какой ресурс нужен, кто его даёт, когда и что ждём на выходе.

Заготовка — `okr-plan.py seed <scope.json> <teamplanner.json>`: KR из принятого
Scope, этапы из `notes.stages`, если был `/okr-stages`. Дальше этапы дописывает
агент с PO и техлидами.

| Поле | Что это |
|---|---|
| `quarter`, `team`, `po`, `status`, `updated` | шапка |
| `scope.file` | Scope, из которого собран план |
| `roles` | типы ресурса, по умолчанию `PO, ADR, SA, BA, BE, FE, QA, DOPS, RM` |
| `teams[]` | `id`, `name`, `external: true` для смежных, `people[]` — `name`, `role` (состав команды) |
| `objectives[]` | `id`, `title`, `krs[]` |
| `krs[]` | `id`, `title`, `pbv`, `tag`, `teams`, `owner` — ответственный, `result` — образ результата из Scope, `comment` — блокеры, сроки, риски |
| `krs[].details` | заметка «Детальнее» — HTML только из тегов `h3 p b strong i em ul ol li br`, без атрибутов: мнения, ожидания, границы, любые мысли для планирования. Нет поля — страница предложит шаблон «Образ действия / Образ результата / Дополнительно»; пустая строка — заметку очистили |
| `krs[].steps[]` | этапы по порядку, ниже |

Этап — `steps[]`:

| Поле | Что это |
|---|---|
| `role` | тип ресурса из `roles` |
| `ext` | id смежной команды, если этап делает она (`EXT[BE]` на странице); пусто — своя команда |
| `title` | что сделать |
| `who` | исполнитель — имя из `teams[].people`; для внешнего этапа не нужен |
| `start`, `end` | даты `ГГГГ-ММ-ДД` |
| `status` | `TODO` · `IN PROGRESS` · `BLOCKED` · `DONE` (на странице — Не начата, В процессе, Заблокирована, Готово) |
| `progress` | 0–100, если нужно точнее статуса |
| `result` | образ результата: что будет готово и как проверить |
| `action` | образ действия: как будем делать — встречи, шаги, договорённости |
| `comment` | всё, что поможет спланировать ресурс |

Роли: `PO` — подготовка и согласования · `ADR` — архитектура · `SA` — системная
аналитика · `BA` — бизнес-аналитика · `BE` — бэкенд · `FE` — фронтенд · `QA` —
тестирование и отладка · `DOPS` — инфраструктура и DevOps · `RM` — выкатка в
прод · `EXT[роль]` — зависимость от внешнего ресурса.

### Что выводит скрипт

| На странице и в CSV | Правило |
|---|---|
| Исполнитель | `ext` → «внешний ресурс: <команда>»; `who` → имя; нет `who` и роли нет в командах KR → «нет роли в команде»; иначе пусто |
| Подсветка подзадачи | сиреневая черта — внешний ресурс · розовая — нет роли в команде · красная рамка исполнителя — роль в команде есть, человек не выбран |
| Прогресс этапа | `progress`, иначе 100 для `DONE` и 0 для остальных |
| Прогресс KR | среднее по этапам, округление половиной вверх |
| Статус KR | все `DONE` → Готово; есть `BLOCKED` → Заблокирована; есть начатые → В процессе; иначе Не начата |
| Сроки KR | самое раннее начало и самый поздний конец этапов |

Эти же правила продублированы в `teamplanner.js` (редактор и кнопка «Скопировать
для Google Sheets») — меняешь в одном месте, меняй и в другом.

### Правки на странице

Страница во всю ширину экрана, без шапки: сверху — текущая цель и кнопки
выгрузки. Один экран — одна цель. У левой кромки две вкладки, у каждой своя
панель: «OBJ N из M» — переключение целей, «Команда» — состав команды. На
экране — KR цели, которые раскрываются в подзадачи. Эта страница, в отличие от ФАКТ и ПЛАН, правится
прямо в браузере, и только самое нужное:

- добавить подзадачу — название по умолчанию равно названию KR;
- удалить подзадачу;
- поменять тип (выпадающий список: роли и `EXT[роль]`), название, исполнителя.

Исполнитель — поле с подсказками «[ТИП] ФИО» из состава: сначала люди с типом
подзадачи. Можно начать печатать часть имени или типа — при единственном
совпадении подставится этот человек; ничего не нашлось или совпадений несколько —
поле вернёт прежнее значение. Пустое поле снимает исполнителя.

Кнопка «Детальнее» у KR открывает справа свободную заметку с простым
форматированием (заголовок, текст, жирный, курсив, списки). По умолчанию в ней
заголовки «Образ действия», «Образ результата», «Дополнительно» — их можно
удалить. Заметка пишется в `details`; вставленный текст чистится до тех же
тегов. В CSV заметка идёт простым текстом в комментарий строки KR.

В панели «Команда» — состав: строки «команда · тип · ФИО» (команда и
ФИО — свободный текст, тип — тот же список ролей). Можно добавить и удалить
участника. Состав пишется в `teams[].people`: команда ищется по названию,
новое название — новая команда (`id` вида `team-N`); внешние команды не
трогаются. Из этого состава выбирают исполнителей подзадач.

Тип `EXT[роль]` ставит `ext` — смежную команду из команд KR, иначе первую
внешнюю. Сроки, статусы и заметки на странице не правятся — их ведёт агент в
JSON, и они уходят в CSV. Правки копятся в браузере; «Скачать JSON» отдаёт
весь документ (`updated` — сегодня, принятый становится черновиком). Агент
кладёт файл на место, прогоняет `lint` и `render`. «Копировать в Sheets» кладёт
в буфер лист целиком — вставляется в таблицу TeamPlanner.

### CSV — `okr-plan.py csv <teamplanner.json> <out.csv>`

Лист в порядке TeamPlanner: строка цели, строка KR «(общий прогресс)», строки
этапов «Название (РОЛЬ)». Колонки: Название · Комментарий · Роль · Исполнитель ·
Начало · Конец · Статус · Прогресс, % · Образ результата · Образ действия.

### Что проверяет `lint`

| Проверка | Уровень |
|---|---|
| Структура: объекты, списки и значения на своих местах | ошибка |
| Формат квартала, id KR, уникальность; команды KR описаны в teams | ошибка |
| `details` — только разрешённые теги без атрибутов | ошибка |
| Роль из `roles`, название, статус, `progress` 0–100, даты `ГГГГ-ММ-ДД`, начало не позже конца | ошибка |
| `who` есть в составе команд, `ext` — описанная команда | ошибка |
| У KR (кроме ACTIVITY) есть этапы | гейт |
| У этапа своей команды есть исполнитель — в том числе когда роли нет в командах KR (тогда ресурс ищут извне) | гейт |
| Каждый KR, взятый в квартал по Scope, есть в TeamPlanner | гейт |
| Сроки вне квартала; `ext` не помечена external; KR нет среди взятых в Scope | предупреждение |

## Комментарии PO для агента

Страницы ничего не правят сами. PO правым кликом по пункту карточки (риск,
фактическая готовность, следующие действия, шаг плана, раздел), по строке
таблицы или по выделенной мышью зоне карточки оставляет комментарий. У
комментария к выделению `quote` — выделенный текст, `section` — все задетые
разделы через « / », `blocks` — задетые пункты. Комментарии копятся в браузере и уходят агенту
кнопкой «Скопировать для агента» (текст в чат) или «Скачать файлом»
(`<файл>.comments.json`):

```json
{"file": "retro-2026Q3.json",
 "comments": [{"kr": "1.1.E1", "section": "Риски", "quote": "…", "text": "Добавь риск: …", "at": "2026-10-01T09:30:00Z"}]}
```

Агент по каждому комментарию правит JSON (`section` подсказывает поле: «Риски»
→ `risks`, «Фактическая готовность» → `pct` и `comment`, «Следующие действия»
→ `next`, «Процессный roadmap» → `plan`), прогоняет `lint` и `render` и
отчитывается по каждому пункту: сделано или почему нет. Комментарий, который
нельзя выполнить без решения PO, — вопрос PO, а не догадка.
