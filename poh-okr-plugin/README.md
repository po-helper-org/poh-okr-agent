# poh-okr-plugin

Раздел «Управление целями» для DeepSeek Harness: доска OKR на квартал, планирование
по спринтам и операционные задачи PO.

Плагин — **необязательная часть** `poh-okr-agent`. Репозиторий остаётся самодостаточным
набором навыков для Claude Code: `install.sh` синкает только `commands/` и `skills/`, эта
папка в установку не попадает и Node.js для команд `/okr-*` не нужен.

## Хранилище

Своего хранилища у плагина нет. Всё живёт в [Backlog.md](https://github.com/MrLesk/Backlog.md)
и читается через его CLI:

| Сущность | Backlog.md |
|---|---|
| Объектив (OBJ) | milestone |
| Ключевой результат (KR) | задача типа `okr` с привязкой к milestone |
| Фаза KR в спринте | метка `okr-phase:s<N>:<фаза>` на задаче KR |
| Операционная задача PO | задача типа `potask`, связь с KR — `--dep` |
| Вкладка панели работы | метка `okr-kind:task` / `okr-kind:control` / `okr-kind:risk` |
| Срок | `--due-date` задачи или объектива |
| Ссылка на Confluence | `--doc` |
| Ссылка на эпик трекера | `--ref` |
| Событие ленты KR | комментарий задачи (`--comment`) |

Связь операционной задачи с KR — зависимость, а не родительство: подзадача получила бы
идентификатор вида `PO-20.1` и стала бы частью KR, тогда как у неё свой жизненный цикл.

Фактические фазы на доске и плановые спринты по стадиям — независимые поля. Плановый
спринт влияет только на граф детальной страницы, фактическая фаза — только на доску.

Писать в `.md` напрямую плагин не умеет и не должен: единственный писатель — CLI, он держит
метаданные задач в согласованном состоянии.

## Требования

**Backlog.md 1.51.0 или новее.** Дедлайны задач и объективов появились именно в нём, а на них
держится группировка панели работы. На версии старше плагин отказывается работать с внятным
сообщением вместо тихой потери функциональности.

```sh
npm i -g backlog.md@latest
```

Типы задач `okr` и `potask` должны быть заведены в воркспейсе. `backlog config set` их не
принимает — CLI отправляет править файл проекта:

```yaml
# backlog/config.yml
types: ["bug", "feature", "enhancement", "task", "chore", "docs", "spike", "okr", "potask"]
```

## Подключение к DeepSeek Harness

1. Собрать пакет:

   ```sh
   cd poh-okr-plugin && pnpm install && pnpm build
   ```

2. Слинковать в каталог плагинов харнесса:

   ```sh
   ln -s "$PWD" <harness>/harness-ui-plugins/poh-okr-plugin
   ```

3. Добавить запись в профиль `web`. `cordis.patch.yml` едет вместе с пакетом и задаёт
   всё, кроме корня воркспейса, — его укажите слоем профиля по идентификатору `okr-goals`:

   ```yaml
   - id: okr-goals
     config:
       workspaceRoot: '/путь/к/воркспейсу'
   ```

4. Перезапустить харнесс и дождаться ответа `200`.

**Плагин без собранного `lib/index.js` роняет харнесс целиком** — cordis считает такую запись
фатальной. Каталог `lib/` не в репозитории, поэтому после свежего клона сборка обязательна.

## Настройки

| Ключ профиля | Переменная окружения | По умолчанию |
|---|---|---|
| `workspaceRoot` | `OKR_WORKSPACE_ROOT` | обязателен |
| `backlogBin` | `OKR_BACKLOG_BIN` | `backlog` |
| `krTaskType` | `OKR_KR_TASK_TYPE` | `okr` |
| `poTaskType` | `OKR_PO_TASK_TYPE` | `potask` |
| `boardDocTitle` | `OKR_BOARD_DOC` | `okr-board` |
| `sessionPath` | `OKR_SESSION_PATH` | пусто (чат в текущем пространстве) |

## Разработка

```sh
pnpm test                                        # разбор и построение команд, без CLI
OKR_WORKSPACE_ROOT=/путь pnpm test               # плюс живой прогон против настоящего backlog
```

Без `OKR_WORKSPACE_ROOT` живые тесты пропускаются и **печатают об этом баннер**: зелёный итог
без живого прогона означает, что разбор реального вывода CLI никто не проверял.
